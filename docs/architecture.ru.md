# Архитектура TaoEditor: решения

Статус на 2026-11-07: ядро и слой движка написаны, лаборатория работает. Это документ про решения и про то, что доказано, а что нет.

## Три вопроса, которые нельзя смешивать

1. **Что мы храним** (источник истины): наше версионное дерево `{ v: 1, content: [...] }`.
2. **Чем редактируем** (движок): ProseMirror, точные версии, наружу его типы не торчат.
3. **Что показываем** (вид): семантический вид (`<strong>`, `<em>`…) в редакторе и в показе (`TaoEditorView`); позже режим «исходник Markdown». Подсказки-маркеры в стиле Obsidian **не делаем** (решение пользователя 2026-11-07: работа без выгоды).

Obsidian и Telegram различаются не движком, а ответами на 1 и 3. Obsidian хранит Markdown-текст (CodeMirror 6) и прячет настоящие символы; Telegram хранит текст и диапазоны, символов нет. Нам нужны и кнопка «выделил → жирный» (марка = флаг на диапазоне, всегда точно), и списки, цитаты и таблицы для статей, поэтому дерево.

## Принятые решения

| Решение | Почему |
|---|---|
| Хранится наше дерево, не JSON ProseMirror и не Markdown | JSON движка привязывает формат к чужой библиотеке (включительность марок на границе — правило движка). Markdown не имеет единого синтаксиса для спойлера, упоминания, эмодзи: каждый клиент начнёт растить диалект |
| HTML не хранится никогда | XSS закрыт по построению: сервер и не-веб клиенты рендерят дерево |
| Профили — белые списки над одной схемой | один движок, одна модель; чат, комментарий, статья отличаются набором узлов и марок |
| Нормализатор — единственные ворота | всё, что входит и выходит, проходит через него; он тотален (не бросает) и идемпотентен (проверено фаззингом на 600 случайных документов на профиль) |
| Один список ссылок (`safeUrl`) | `https`/`http`, без логина, без пробелов и управляющих символов; позже тот же для картинок и вставок |
| Схема ProseMirror строится из описаний ядра | что разрешено — решает `core`; движок знает только «как выглядит в DOM» и как читать вставку |
| ProseMirror закреплён точными версиями | 8 пакетов MIT, три мелких листа зависимостей (`orderedmap`, `w3c-keyname`, `rope-sequence`), проверено по npm 2026-11-07. Копирование в репозиторий (vendoring) отложено до публикации |
| Движок можно заменить | наружу идёт наш API и наш документ; конвертер и схема лежат в одном слое `src/editor` |
| Markdown — ввод, экспорт и режим «исходник», не буфер | см. первую строку |
| Идея Editor.js берётся как API расширений | Block Tool = узел + пункт меню + правило ввода; Inline Tool = марка + кнопка; Block Tune = атрибут блока + пункт меню. Сам Editor.js не берём: блок-острова, inline хранится HTML-строкой, выделение не течёт через блоки (из памяти, не проверено) |

## Что доказано и чем

- Нормализатор, ссылки, простой текст: 73 теста в node, в том числе фаззинг на идемпотентность.
- Правила ввода, Backspace-откат, Enter и композиция, ссылки, вставка враждебного HTML, круг «документ ⇄ движок» по всем фикстурам: тесты в jsdom.
- **В реальном Chromium руками** (лаборатория, настоящие нажатия клавиш): `**foo**` даёт `<strong>`, Backspace возвращает `**foo**`, Enter отправляет `"hi\nthere"` (Shift+Enter — перенос), корпус вставок (Google Docs, Word, скрипт/onerror/iframe, ссылки `javascript:`/`data:`, структура) остаётся в рамках схемы.
- Рендер и показ: тесты на экранирование и враждебный документ, **равенство серверного вывода Vue и `toHtml` по всем фикстурам**, спойлер (клик, Enter, пробел, новый документ закрыт); `tests/layers.test.ts` охраняет слои и запрещает `innerHTML` и `eval` в `src`. В реальном браузере: «Look» TaoUI тёмный и светлый берёт токены TaoUI.
- Ломающая проверка (`npm run mutate`): 33 мутанта по защитам (ядро, ссылки, рендер, показ, правила ввода), все пойманы. Первый прогон пропустил 2 мутанта (протокол ссылки был прикрыт проверкой пустого хоста; профиль с урезанным списком марок не тестировался): тесты добавлены.

## Что НЕ проверено (это главный риск)

- **IME**: Android (Chrome + Gboard, клавиатура Samsung), японский и корейский ввод с композицией через границу жирного, Enter во время композиции на реальном устройстве; iOS Safari. В jsdom и на десктопе это не воспроизводится. Задача лаборатории №1: открыть `/lab/` на телефоне (`npm run dev -- --host`) и записать каждый сбой по журналу событий.
- **Телефон, 2026-11-07:** пользователь открыл лабораторию на телефоне (по сети) и остался доволен обычным вводом. Какое устройство и браузер, журнал событий не сохранён. **Иероглифы (японский, корейский, композиция через границу жирного) не проверялись**: пользователь попробует позже; пока полагаемся на то, что есть.
- Firefox и Safari на десктопе, копирование из редактора, ввод в RTL.
- Вставка из системного буфера (Ctrl+V) с реальным Word: проверена только вставка HTML через тот же путь (`pasteHTML`).

## Ворота лаборатории

Если на телефоне в профиле `chat` композиция, Enter или выделение ломаются так, что обойти нельзя, откатываемся на **два ввода на общем ядре**: лёгкий композер «строка + диапазоны» для чата и комментариев и редактор для заметок и статей. Модель, нормализатор, список ссылок и рендер от этого не меняются, поэтому откат дёшев. Пока такого сбоя не видели, но и не искали на устройствах.

## Открытые решения

- **Зерно undo.** Сейчас правило ввода входит в группу истории с набранными символами, и undo откатывает всю фразу, а не только форматирование (закреплено тестом). Первый Backspace после правила возвращает `**foo**`. Выбрать и зафиксировать окончательно после лаборатории.
- **Сериализация не нужна.** Документ это JSON: в базе JSON (или текст), по сети его сожмёт gzip/brotli транспорта, при нужде в одном файле это zip, как делает docx. Бинарный кодек (2pack) нужен там, где важны скорость, трафик и объём (сетевой стек игр, протоколы), а у текстового документа таких причин нет. Предложение Grok про `doc-codec` и плоское представление не берём.
- **Markdown-подмножество**: диалект с явным списком конструкций статьи, которые экспорт не умеет выразить.
- **Vendoring ProseMirror** и `THIRD-PARTY-NOTICES.md` до первой публикации.
## Как редактор живёт в экосистеме Tao*

Приоритет: TaoUI. Но «другие тоже могут» нам почти ничего не стоит, если держать три правила (ровно как в TaoUX).

1. **Ярусы импортов, TaoUI только на самом верху.** `core` (модель, схема, нормализатор, рендер) не импортирует ничего, `editor` знает только движок и ядро, `vue` знает Vue, ядро и редактор. Импортировать TaoUI можно только файлам в `src/vue/taoui/` (сборка редактора из компонентов TaoUI: панель, меню, диалог ссылки). Это проверяет `tests/layers.test.ts`. Кто TaoUI не использует, берёт ядро, движок и показ и пишет свою панель.
2. **Вид на переменных `--te-*` с запасными значениями.** Редактор и показ выглядят прилично сами (светлая и тёмная тема по `color-scheme`), настраиваются переменными на `:root` или на любом предке. Прямо цветов и шрифтов в правилах нет.
3. **Мост `taoui.css` одним импортом** наводит `--te-*` на токены `--tao-*` (нулевая специфичность, без зависимости от пакета TaoUI, тот же приём, что `@1337exp/taoux/taoui.css`). Типографику текста берёт на себя сам TaoUI: класс `tao-prose` на редакторе и на показе (у нас для этого `class` в `createEditor` и обычный `class` у `TaoEditorView`); наши нейтральные правила при `tao-prose` отступают.

Упаковка как у TaoUX: подпути без корневого входа (`/core`, `/editor`, `/vue`, `/content.css`, `/editor.css`, `/taoui.css`), `vue` и `@1337exp/taoui` необязательные peer-зависимости.

Проверено в браузере: «Look» в лаборатории (нейтральный, TaoUI тёмный, TaoUI светлый): граница, фон, радиус, шрифт поля берутся из токенов TaoUI, класс `tao-prose` ставится, возврат к нейтральному вида снимает всё.

Чего ещё нет: готового Vue-компонента `TaoEditor` в `vue/taoui/` (панель на TaoUI, `v-model` + `change`, размеры `small / medium / large`, плотность, `*Label` для скринридера: правила API TaoUI).
