# Архитектура TaoEditor: решения

Статус на 2026-11-07: ядро и слой движка написаны, лаборатория работает. Это документ про решения и про то, что доказано, а что нет.

## Три вопроса, которые нельзя смешивать

1. **Что мы храним** (источник истины): наше версионное дерево `{ v: 1, content: [...] }`.
2. **Чем редактируем** (движок): ProseMirror, точные версии, наружу его типы не торчат.
3. **Что показываем** (вид): семантический вид (`<strong>`, `<em>`…) в редакторе и в показе (`TaoEditorView`); позже режим «исходник Markdown». Подсказки-маркеры в стиле Obsidian **не делаем** (решение пользователя 2026-11-07: работа без выгоды).

Obsidian и Telegram различаются не движком, а ответами на 1 и 3. Obsidian хранит Markdown-текст (CodeMirror 6) и прячет настоящие символы; Telegram хранит текст и диапазоны, символов нет. Нам нужны и кнопка «выделил → жирный» (марка = флаг на диапазоне, всегда точно), и списки, цитаты и таблицы для статей, поэтому дерево.

## Принятые решения

| Решение | Почему |
|---|---|
| Хранится наше дерево, не JSON ProseMirror и не Markdown | JSON движка привязывает формат к чужой библиотеке (включительность марок на границе — правило движка). Markdown не имеет единого синтаксиса для спойлера, упоминания, эмодзи: каждый клиент начнёт растить диалект |
| HTML не хранится никогда | XSS закрыт по построению: сервер и не-веб клиенты рендерят дерево |
| Профили — белые списки над одной схемой | один движок, одна модель; чат, комментарий, статья отличаются набором узлов и марок |
| Нормализатор — единственные ворота | всё, что входит и выходит, проходит через него; он тотален (не бросает) и идемпотентен (проверено фаззингом на 600 случайных документов на профиль) |
| Один список ссылок (`safeUrl`) | `https`/`http`, без логина, без пробелов и управляющих символов; позже тот же для картинок и вставок |
| Схема ProseMirror строится из описаний ядра | что разрешено — решает `core`; движок знает только «как выглядит в DOM» и как читать вставку |
| ProseMirror закреплён точными версиями | 7 пакетов MIT, три мелких листа зависимостей (`orderedmap`, `w3c-keyname`, `rope-sequence`), проверено по npm 2026-11-07. Копирование в репозиторий (vendoring) отложено до публикации |
| Движок можно заменить | наружу идёт наш API и наш документ; конвертер и схема лежат в одном слое `src/editor` |
| **Markdown в редакторе нет совсем**: ни ввода, ни сокращений, ни режима «исходник», ни импорта | набранное и вставленное остаётся тем, чем было: либо текст явно форматирован, либо это просто текст (решение пользователя 2026-11-07). Актуальна только возможная выгрузка в `.md` |
| Идея Editor.js берётся как API расширений | Block Tool = узел + пункт меню; Inline Tool = марка + кнопка; Block Tune = атрибут блока + пункт меню. Сам Editor.js не берём: блок-острова, inline хранится HTML-строкой, выделение не течёт через блоки (из памяти, не проверено) |

## Что доказано и чем

- Нормализатор, ссылки, простой текст: 73 теста в node, в том числе фаззинг на идемпотентность.
- Ввод никогда не превращается в разметку (в том числе вставка текста, похожего на Markdown), Enter и композиция, ссылки, вставка враждебного HTML, круг «документ ⇄ движок» по всем фикстурам: тесты в jsdom.
- **В реальном Chromium руками** (лаборатория, настоящие нажатия клавиш): набранный `**x**` остаётся текстом, Enter отправляет `"hi
there"` (Shift+Enter — перенос), корпус вставок (Google Docs, Word, скрипт/onerror/iframe, ссылки `javascript:`/`data:`, структура) остаётся в рамках схемы, плавающая панель форматирует выделенное слово и не сбрасывает выделение.
- Рендер и показ: тесты на экранирование и враждебный документ, **равенство серверного вывода Vue и `toHtml` по всем фикстурам**, спойлер (клик, Enter, пробел, новый документ закрыт); `tests/layers.test.ts` охраняет слои и запрещает `innerHTML` и `eval` в `src`. В реальном браузере: «Look» TaoUI тёмный и светлый берёт токены TaoUI.
- Узлы с `key` в `TaoEditor` (хост, панель, форма ссылки) страхуют друг друга: достаточно любого, поэтому поодиночке мутанты эквивалентны. Регрессионный тест (DOM редактора остаётся в своём хосте) проверен вручную: без всех ключей он падает.
- Ломающая проверка (`npm run mutate`): 49 мутантов по защитам (ядро, ссылки, рендер, показ, компонент), все пойманы. Первый прогон пропустил 2 мутанта (протокол ссылки был прикрыт проверкой пустого хоста; профиль с урезанным списком марок не тестировался): тесты добавлены.

## Что НЕ проверено (это главный риск)

- **IME**: Android (Chrome + Gboard, клавиатура Samsung), японский и корейский ввод с композицией через границу жирного, Enter во время композиции на реальном устройстве; iOS Safari. В jsdom и на десктопе это не воспроизводится. Задача лаборатории №1: открыть `/lab/` на телефоне (`npm run dev -- --host`) и записать каждый сбой по журналу событий.
- **Телефон, 2026-11-07:** пользователь открыл лабораторию на телефоне (по сети) и остался доволен обычным вводом. Какое устройство и браузер, журнал событий не сохранён. **Иероглифы (японский, корейский, композиция через границу жирного) не проверялись**: пользователь попробует позже; пока полагаемся на то, что есть.
- Firefox и Safari на десктопе, копирование из редактора, ввод в RTL.
- Вставка из системного буфера (Ctrl+V) с реальным Word: проверена только вставка HTML через тот же путь (`pasteHTML`).

## Ворота лаборатории

Если на телефоне в профиле `chat` композиция, Enter или выделение ломаются так, что обойти нельзя, откатываемся на **два ввода на общем ядре**: лёгкий композер «строка + диапазоны» для чата и комментариев и редактор для заметок и статей. Модель, нормализатор, список ссылок и рендер от этого не меняются, поэтому откат дёшев. Пока такого сбоя не видели, но и не искали на устройствах.

## Открытые решения

- **Сериализация не нужна.** Документ это JSON: в базе JSON (или текст), по сети его сожмёт gzip/brotli транспорта, при нужде в одном файле это zip, как делает docx. Бинарный кодек (2pack) нужен там, где важны скорость, трафик и объём (сетевой стек игр, протоколы), а у текстового документа таких причин нет. Предложение Grok про `doc-codec` и плоское представление не берём.
- ~~Vendoring ProseMirror~~ **не делаем** (решение пользователя 2026-11-07): ProseMirror остаётся обычной зависимостью из npm, точные версии. Копировать его в репозиторий и вести `THIRD-PARTY-NOTICES.md` не нужно, потому что в нашу сборку он не попадает (внешняя зависимость).
## Чат: упоминания и эмодзи

- **Упоминание это атом** (`mention`: `id` + `label`). `id` проверяется тем же нормализатором (буквы, цифры, `_ . : -`, до 64), `label` чистится (управляющие символы, пробелы) и не длиннее 80; плохое упоминание выпадает из документа, соседний текст остаётся. Вставленная разметка `span[data-mention]` проходит те же проверки. **`id` внутри документа лишь заявление:** кто кого может упомянуть и существует ли человек, проверяет сервер приложения, не редактор. Подпись это снимок на момент вставки, показ не ходит за актуальным именем.
- **Триггер `@`** в движке (`src/editor/mentions.ts`) без интерфейса: каретка внутри `@запрос` после пробела, скобки или в начале блока (адрес `a@b` не триггер; не в блоке кода и не под меткой кода) даёт хосту `onTrigger({ query, from, to })`. Escape гасит список для этой `@`. Стрелки, Enter, Tab уходят хосту; если выбирать нечего, Enter работает как обычно (в чате отправляет). Список и данные принадлежат приложению (`mentions` у `TaoEditor`: функция запроса, ответ сейчас или промисом; поздний ответ на старый запрос отбрасывается; сбой поиска = пустой список).
- **Гонка Enter против ответа.** Если нажать Enter раньше, чем пришёл ответ поиска, Enter сработает как обычный (в чате отправит `@bo` текстом). Это безопасный отказ: ничего не превращается неверно. Если на медленном сервере это будет мешать, можно задерживать Enter, пока идёт запрос.
- **Эмодзи пока только Юникод**: выбор из списка вставляется обычными символами (`insertText`), особого узла нет, хранятся только символы. **Кастомные эмодзи-картинки (по id) не делаем, пока нет решения:** им нужны каталог, хранение файлов и правила (кто загружает, где лежит, что видят чужие клиенты).
- Не проверено: список подсказок и панель эмодзи на сенсорных устройствах, с клавиатурами Android и иероглифами; упоминание в IME-композиции (триггер при композиции не срабатывает).

## Панель как у Google (форматирование)

- Порядок как у Gmail: отмена и повтор | жирный, курсив, подчёркнутый, зачёркнутый, код, спойлер, ссылка | нумерованный, маркированный, уменьшить и увеличить отступ, цитата | очистить форматирование. Кнопки блоков показываются по профилю (в `chat` нет списков и отступов, цитата есть).
- **Подчёркнутый** это метка `underline` (`<u>`). Ссылка и код её вытесняют: ссылка и так подчёркнута, у кода своё оформление.
- **Списки** на `prosemirror-schema-list` (MIT, точная версия, зависимости только свои): Enter в пункте даёт новый пункт, Enter в пустом последнем пункте выходит из списка, Tab вкладывает под предыдущий пункт (у первого нельзя), Shift+Tab поднимает, Tab вне списка достаётся браузеру (фокус идёт дальше). Клавиши Ctrl+Shift+7 / 8 / 9, как у Gmail.
- **Очистка форматирования** снимает все метки выделения кроме ссылки и не трогает структуру (список остаётся списком).
- Радиусы идут через мост: поле `--te-field-radius`, панели и список `--te-panel-radius`, код и метки `--te-radius` на токены `--tao-radius-*`. Метка упоминания и спойлер были вписаны числом, теперь тоже на `--te-radius`.
- **Чего у Google ещё есть и у нас нет:** шрифт (семейство), размер шрифта, цвет текста, выравнивание. Это не кнопки, а новые возможности модели (метка цвета, атрибут выравнивания, размер). Решение за пользователем, см. разговор: цвет и выравнивание делаются просто, размер лучше выразить заголовками или двумя-тремя ступенями, семейство шрифта не рекомендуется (ломает тему экосистемы).

## Возможности под проект (решение пользователя 2026-11-07)

- **Профиль это и есть набор возможностей.** `withoutFeatures(база, { marks, nodes, features })` и `defineProfile({ name, nodes, marks, features, spaced })` делают профиль под проект; `TaoEditor` и `TaoEditorView` принимают и имя, и объект. Что профиль не содержит, пропадает **везде сразу**: кнопка панели, горячая клавиша (команда это «ничего»), вставка (метки нет в схеме движка, вставленный жирный приходит простым текстом, остальное форматирование остаётся), показ сохранённого документа (нормализатор убирает с замечанием `bad-mark`). Опечатки и имена вроде `constructor` бросают ошибку, не проходят молча.
- **Атрибуты блока** (`indent`, `align`) это «features» профиля: `chat` без них, `comment` и `article` с ними. Нет возможности, нет атрибута в схеме и в документе (тихо, без замечаний: документ богаче профиля это нормально).
- **Связанное убирается само**: нет списков, нет и `listItem`; `paragraph`, `text` и переносы строки убрать нельзя.
- Нашлось тестом: схема ProseMirror падала, если в профиле нет метки, которую вытесняет другая (`code` вытесняет `bold`). Вытеснения теперь режутся по меткам профиля.

## Выравнивание и размер (2026-11-07)

- **Выравнивание** `align`: `left` (по умолчанию, не пишется, следует направлению текста), `center`, `right`, `justify`; атрибут `paragraph` и `heading`, показ классом `tao-align-*`. Вставка читает наш класс, `text-align` и атрибут `align` (Docs, Word, Gmail).
- **Размер** `size`: метка с тремя значениями `small`, `large`, `huge` (обычный = без метки), показ классом `tao-text-*`, размеры меняются переменными `--te-size-*`. Из вставки размеры шрифта страниц **не берутся** (11pt, 24pt и так далее это не выбор), только `<small>`, `<big>` и наши классы.
- **Попапы** выравнивания, размера и цветов один механизм: абсолютно позиционированный блок под кнопкой (над ней, если снизу нет места), измеряется после отрисовки, один попап за раз, закрывается нажатием снаружи и Escape.

## Цвет текста и фона (решение пользователя 2026-11-07: цвета произвольные)

- **Две метки**: `color` и `background`, значение одно: `#rrggbb` в нижнем регистре. Разбор (`parseColor`, `src/core/color.ts`) принимает `#rgb`, `#rrggbb`, `rgb()` и `rgba()` с альфой 1 и **отвергает всё остальное** (имена, `hsl`, `var()`, `url()`, всё с `;` или кавычкой, прозрачное, длиннее 40 знаков). Плохое значение снимает метку, текст остаётся.
- **Показ inline-стилем** (`style="color:#ff0000"`), потому что цвета произвольные и классами их не выразить. Значение это проверенный hex, ничего другого в style попасть не может (проверено тестами и мутантами). Цена: строгая политика CSP без `style-src 'unsafe-inline'` такие стили заблокирует. Если такая политика понадобится, переход на `data-`атрибут и CSS-переменную делается в одном месте (`render.ts`).
- **Вставка**: цвета из HTML берутся, **кроме чёрного и белого** (`isPageInk`). Docs, Word и Gmail ставят `color:#000000` на каждый кусок и `background:#ffffff` под него; взять их значило бы сделать текст чёрным на тёмной теме. В палитре чёрный и белый выбираются намеренно.
- **`code` вытесняет цвета**; цвет и ссылка уживаются. Цвет не меняет простой текст.
- **Попап, не блок** (поправка после замечания пользователя, как у Gmail): панель цветов абсолютно позиционирована, открывается под кнопкой «A» (над ней, если снизу нет места), прижимается к краям компонента, **ничего на странице не сдвигает** (проверено измерением: корень, поле и всё ниже остаются на местах). Место измеряется после отрисовки, до этого панель скрыта (`visibility`), чтобы не мелькать в углу. Ширина по содержимому (`max-content`), иначе сдвиг вправо сжимает её и вторая секция уходит под первую.
- **Панель**: кнопка «A» открывает попап из двух секций (текст, фон) по 80 ячеек (набор как у Google Docs), кнопки «По умолчанию» и поле своего цвета (`TaoColorInput`). Стрелки ходят по ячейкам, Tab-остановка одна, Escape и нажатие снаружи закрывают. Попап `TaoColorInput` монтируется в `body` (`.tao-popover__panel`), поэтому нажатие в нём не считается «снаружи».
- **Контраст не наша забота** (решение пользователя 2026-11-07): палитра для того и существует, чтобы каждый выбирал сам; цвет, который «прыгает» при смене темы, и проверки контраста требуют решений продукта, а не редактора. Не делаем, пока такое решение не появится.

## Интервал, отступы, Tab (решения 2026-11-07)

- **Почему интервал у Gmail и у нас разный.** Gmail на Enter делает строку (`<div>` без зазора). Reddit, Notion, Docs делают абзац (`<p>` с зазором). У нас Enter это новый абзац (модель одна), а зазор между абзацами не часть модели, а вид. Под TaoUI он ещё и крупнее, потому что `.tao-prose` рассчитан на статьи.
- **Переключатель нужен, он дёшев** (это только CSS): `spaced` у `TaoEditor` и `TaoEditorView`. **По умолчанию: зазор только у профиля `article`, у `chat` и `comment` строка без зазора** (как в почте и чатах). Хранимый документ не меняется. Два класса (`.tao-compact` вместе с `.tao-editor` или `.tao-content`) перебивают `tao-prose`.
- **Отступы у обычных строк**: у `paragraph` и `heading` атрибут `indent` от 0 до 8 (0 не пишется), показ классом `tao-indent-N` (никаких inline-стилей), `--te-indent` меняет шаг (2em). Кнопки: в пункте списка вкладывают его, иначе меняют отступ у всех выделенных строк. Вставка: наш класс или левое поле Gmail (40px), Docs и Word (36pt) переводится в ближайший уровень, не больше 8.
- **Tab перехватить можно** (браузер это разрешает; в лаборатории настоящий Tab вложил пункт списка), но **нельзя без оглядки**: перехваченный Tab это ловушка для клавиатуры (WCAG). Поэтому: Tab вкладывает пункт, только если есть пункт перед ним, иначе фокус идёт дальше; Shift+Tab поднимает только вложенный пункт, на верхнем уровне фокус идёт назад; в обычном абзаце Tab не перехватывается совсем. Вывести пункт из списка можно кнопкой панели и Enter на пустом пункте.
- **Контракт моста** (как в TaoUX 0.9): `tests/bridge.test.ts` требует, чтобы мост был единственным файлом с `--tao-*`, чтобы каждая цветовая, шрифтовая, радиусная и теневая переменная `--te-*`, которую мы читаем, была в мосте, чтобы в мосте не было лишнего и чтобы токены существовали в установленном TaoUI (читаются его `src/styles`). Тест сразу нашёл `--te-error` (цвет ошибки формы ссылки), которого не хватало.

## Как редактор живёт в экосистеме Tao*

Приоритет: TaoUI. Но «другие тоже могут» нам почти ничего не стоит, если держать три правила (ровно как в TaoUX).

1. **Ярусы импортов, TaoUI только на самом верху.** `core` (модель, схема, нормализатор, рендер) не импортирует ничего, `editor` знает только движок и ядро, `vue` знает Vue, ядро и редактор. Импортировать TaoUI можно только файлам в `src/vue/taoui/` (сборка редактора из компонентов TaoUI: панель, меню, диалог ссылки). Это проверяет `tests/layers.test.ts`. Кто TaoUI не использует, берёт ядро, движок и показ и пишет свою панель.
2. **Вид на переменных `--te-*` с запасными значениями.** Редактор и показ выглядят прилично сами (светлая и тёмная тема по `color-scheme`), настраиваются переменными на `:root` или на любом предке. Прямо цветов и шрифтов в правилах нет.
3. **Мост `taoui.css` одним импортом** наводит `--te-*` на токены `--tao-*` (нулевая специфичность, без зависимости от пакета TaoUI, тот же приём, что `@1337exp/taoux/taoui.css`). Типографику текста берёт на себя сам TaoUI: класс `tao-prose` на редакторе и на показе (у нас для этого `class` в `createEditor` и обычный `class` у `TaoEditorView`); наши нейтральные правила при `tao-prose` отступают.

Упаковка как у TaoUX: подпути без корневого входа (`/core`, `/editor`, `/vue`, `/content.css`, `/editor.css`, `/taoui.css`), `vue` и `@1337exp/taoui` необязательные peer-зависимости.

Проверено в браузере: «Look» в лаборатории (нейтральный, TaoUI тёмный, TaoUI светлый): граница, фон, радиус, шрифт поля берутся из токенов TaoUI, класс `tao-prose` ставится, возврат к нейтральному вида снимает всё.

`TaoEditor` лежит в `src/vue/taoui/` (панель на `TaoToolbar` и `TaoButton` с `pressed`, поле ссылки на `TaoInput`, `size`, `labels`, `v-model` + `change` + `send`). Показ (`TaoEditorView`) отдельным входом и ярус `taoui` не тянет: это проверяет тест слоёв.

Под руководство по дизайну TaoUI (5.30): панель из `ghost` + `tone="neutral"` (включённый переключатель единственный яркий), размер обычный (medium), **решение пользователя 2026-11-07 вопреки совету руководства про `small` для панелей инструментов**: поле и его эмодзи это то, чем пользуются, а не побочный инструмент (так же сделано в Gmail); `size` меняет размер панели, списка эмодзи и формы ссылки; сами эмодзи крупнее подписи кнопки; клавиши в подсказке кнопки (`Bold (Ctrl+B)`) штатно, без обходов. Минимум TaoUI теперь `^5.30.0`.

### Что, если мост к TaoUI сломается

- Переменная, указывающая на несуществующий токен, не ломает вид: `var(--te-x, запасное)` берёт запасное значение (нейтральный вид). Деградация мягкая.
- Поломку ловит `tests/bridge.test.ts`: он читает токены, которые объявляет **установленный** TaoUI, и требует, чтобы каждый `--tao-*` из `taoui.css` там был. Переименовали токен в TaoUI, обновили зависимость, тест называет, какой именно.
- Весь мост — один файл на ~20 строк; чинится в одном месте. Прямая привязка всех правил к `--tao-*` разнесла бы то же самое по всему CSS и без запасного вида.
- Настоящая связь с TaoUI одна и намеренная: компонент `TaoEditor` использует API компонентов TaoUI (`pressed`, `size`, `TaoToolbar`). Её держит peer-диапазон `^5` и тесты компонента.
